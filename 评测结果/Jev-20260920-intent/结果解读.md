# Jev 1.13 与原 GLM 意图识别方案：实测结果

2026-09-20 完成 48 对、共 96 次真实 API 请求，全部 HTTP 200，无重试。结果支持继续研究 Jev 的英文分类效果，暂不支持直接替换当前中文客服的意图识别方案。

## 结果

主指标比较原方案的模型语义分类分支，不包含订单执行、RAG 或答复生成。

| 指标 | GLM-4.5-Air 原方案 | OpenRouter Jev 1.13 |
|---|---:|---:|
| 总体正确数 | 37 / 48 | 41 / 48 |
| 总体准确率 | 77.08% | 85.42% |
| 四类 Macro-F1 | 0.8603 | 0.9164 |
| 中文正确数 / 准确率 | 22 / 24，91.67% | 22 / 24，91.67% |
| 英文正确数 / 准确率 | 15 / 24，62.50% | 19 / 24，79.17% |
| 中位调用耗时 | 655 ms | 976 ms |
| P95 调用耗时 | 800 ms | 1,048 ms |
| 接口失败数 | 0 | 0 |

Jev 多答对 4 条，均为英文；没有出现 GLM 正确而 Jev 错误的配对。精确 McNemar 检验 p=0.125，小样本下不足以按 0.05 门槛断言存在稳定的准确率提升。48 条样本并非独立人工验收集，中文为运行前编写的合成样本，结论仅适用于本次探索。

Jev 的中位耗时约为 GLM 的 1.49 倍。这里比较的是本机到“OpenRouter→TypeSafe”和“智谱直连”的完整调用路径，包含网络、路由及接口封装耗时，不等于模型内部推理速度。

## 改善发生在哪些样本

| 英文表达（节选） | 预期 | GLM | Jev |
|---|---|---|---|
| help to get my bill from ... | invoice | billing | invoice |
| ... getting my ... bill from ... | invoice | billing | invoice |
| i do not know how to speak with an assistant | human_handoff | other | human_handoff |
| I need assistance to locate order ... | order_status | query | order_status |

主要变化是从宽泛类别细分到业务类别。这里使用 Bitext 原始标签到本项目类别的公开映射；英文 bill 等表达存在边界歧义，不应把这些少量结果当成全面语义能力排名。

## 保留现有融合规则会怎样

原项目还会把模型结果与关键词规则融合，并把低分结果降级为 other。作为附加诊断，本次也计算了该步骤：

- 原 GLM 融合后：37 / 48，77.08%。
- Jev 使用获选类别概率参与原融合规则后：39 / 48，81.25%。

Jev 原始分类正确的两条在旧阈值下被降级，说明接入时不能只替换 API。Jev 的概率、Jev 返回的 confidence 和 GLM 自报 confidence 含义不同；本次没有在测试集上调阈值。这组融合结果仅作诊断，不能当作已完成校准的候选方案。

## 环境与可复查材料

- Windows、Python 3.14.6，隔离环境 `.runtime/jev-eval-venv`。
- GLM：原 `IntentRecognizer` 提示词和解析、原 `Model` 适配器，`glm-4.5-air`，temperature=0，输出上限 256，thinking=disabled。
- Jev：请求模型 `typesafe/jev-1.13`，返回模型 `typesafe/jev-1.13-20260917`，provider=TypeSafe；OpenRouter `/api/alpha/decisions` 原生 Choice 接口。
- 中英文各 24 条，退款/发票/订单状态/转人工各 12 条，两个模型都从完整 19 类选择。
- 每条请求交替模型先后顺序，串行执行，未调整提示词、阈值或标签后重跑。
- 7 项离线检查通过：数据平衡与标签隔离、错误计分、预算拒绝、超时预留、费用记录、概率校验、配对统计。
- 同目录 `report.json` 保存统计和逐条预测；`复现数据与源码.zip` 包含环境、依赖锁、源码快照、冻结数据集、请求/响应和预算台账，不含密钥。
- 操作说明位于仓库 `evaluation/JEV_INTENT_EXPERIMENT.md`。

## 对项目的建议

保留 GLM 作为当前中文客服默认方案。Jev 可作为英文意图分类候选继续测试，但这次没有观察到中文正确率改善，实际调用也更慢。下一步若继续，应增加独立标注的自然中文与业务边界样本，在开发集校准概率和拒答阈值，再用未见过的测试集复核。生产路由本次未修改。

接口依据：[OpenRouter 模型页](https://openrouter.ai/typesafe/jev-1.13/)、[OpenRouter OpenAPI](https://openrouter.ai/openapi.json)、[TypeSafe 已知限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。
