# 读完资料后，怎样确认自己真的懂了

输入：源码页、结构图和请求推演。输出：你能独立画图、算分、定位问题、给出验证方法。以下任务从整体到细节，完成标准是能推导行为，而不是记住文件名。

## 第一阶段：画出一个请求

先读[结构地图](01_结构地图.md)，然后打开 [api/main.py](逐文件/api/main.py.md) 的 lifespan、chat、_build_knowledge_context。合上资料，在纸上画出 HTTP→记忆→意图→RAG→编排→生成→写记忆；在每条箭头写对象/字段，不要只画模块框。

完成标准：能解释 conv_id 谁创建、历史传给谁、entities 谁填、Skills 在何时注入、画像何时更新。说出 CLI/评测少了哪几步。若只能说“用了 Redis、RAG、多 Agent”，还没有完成这一阶段。

## 第二阶段：现场算一次路由

读 [intent_recognizer](逐文件/core/intent_recognizer.py.md) 的投票与实体，读 [agent_orchestrator](逐文件/agents/agent_orchestrator.py.md) 的领域分数和辅助条件。

练习：给定 intent=technical_login、消息“登录一直 401，而且刚才还重复扣款了”，不要调用模型，计算三个领域得分。再改变金额、关键词、意图，观察是否进入并行。说明为什么强化主意图可能反而减少辅助 Agent。

答案校验：有空格包围401时正则能提错误码，示例得 technical=1.13、billing=.18，不并行；连续中文与数字间的 `\b` 边界行为可能影响实体匹配，因此推演必须与确切字符串一致。完整固定字符串见[验证记录](06_验证记录.md)。不能只看中文语义就假定正则结果。

完成标准：分清 intent_confidence、routing_confidence、routing_score 三个数；知道 default pool 每类只有一个实例。

## 第三阶段：跟着一次检索找证据

读 [tool_manager](逐文件/mcp/tool_manager.py.md) 的 call、search_with_rewrite、_rerank，再读 [knowledge_base](逐文件/mcp/knowledge_base.py.md) 的导入和搜索。

练习：画出缓存、熔断、校验、超时的先后顺序，回答“缓存命中时还会检查熔断吗”“use_cache=False会写缓存吗”“候选只有两条时是否调用重排模型”“知识库失败时knowledge_used可能是什么”。

答案要点：命中可绕过熔断；False只关读仍可能写；候选≤k跳过模型；fallback非空可能误标True。完成标准：能把“服务没报错”和“拿到了有用知识”分开。

## 第四阶段：动手推导状态变化

读 [conversation_memory](逐文件/memory/conversation_memory.py.md)，用1..15代替消息，按代码模拟LPUSH、reversed、keep与delete。之后运行本文件夹的离线验证脚本，检查自己的推导是否一致。

练习：当第16条在压缩等待LLM时到达，会不会丢？旧摘要会不会越积越长？同用户不同conv保存两份画像后limit=1保证最新吗？短会话退出后是否自动进入episodic？

答案要点：可能丢；会追加增长；不保证；不会，只有触发压缩才归档情景摘要。完成标准：能给出会话锁/版本CAS的目的，并解释为什么只修改reversed不能解决并发丢失。

## 第五阶段：讲清监控和评测的分工

读 [performance_monitor](逐文件/monitor/performance_monitor.py.md) 与 [evaluator](逐文件/evaluation/evaluator.py.md)。画两条反馈链，指出有没有Evaluator→Monitor→prompt修改的自动连接。

练习：解释一次11条意图分类+7轮对话为什么报告total=8；为什么历史baseline中的100%不是生产准确率；为什么当前Histogram不能直接算真实请求P95。

答案要点：整组分类只占1项；样本小、标签版本不同、裁判无事实证据；采的是累计均值而非每请求延迟。完成标准：能提出一套统一入口评测和分段埋点方案，而不是只要求“再加一些测试”。

## 二十分钟模拟面试

| 时间 | 面试官任务 | 你应该展示的东西 |
|---|---|---|
| 0–2分钟 | 介绍项目与自己的工作 | 真实职责、业务目标、最关心的设计 |
| 2–5分钟 | 画完整请求链路 | 输入输出对象、存储与模型调用位置 |
| 5–9分钟 | 解释多Agent为什么触发/不触发 | 领域分数、辅助阈值、实例评分 |
| 9–12分钟 | RAG失败如何处理 | 超时、熔断、fallback、证据状态 |
| 12–15分钟 | 追问记忆正确性 | LPUSH时序、压缩并发、画像来源 |
| 15–18分钟 | 怎样证明改动更好 | 数据集版本、消融、完整链路、指标口径 |
| 18–20分钟 | 下一步先做什么 | 有优先级和验收标准的一个具体改进 |

## 快速自测：至少能独立回答这些问题

1. `mcp/` 名字为什么不能证明实现了MCP协议？
2. `BaseAgent._call_llm` 的messages里究竟放了什么？有没有tools？
3. API和编排器都能识别意图，HTTP会重复调用吗？
4. `history[-3:]`是三条还是三轮？对信息保留有什么影响？
5. 谁把实体送到路由器？CLI为什么不一样？
6. 为什么“出现两个领域关键词”不保证并行？
7. primary_agent和实际agent_type何时不同？
8. escalation没有实例时，谁生成回复？有没有实际通知人工？
9. 监控penalty改变以后，单实例池会换路由吗？
10. 查询改写失败和知识handler失败走相同fallback吗？
11. 按str(item)去重为什么受score影响？
12. 500字符切片为什么可以产生1200字符片段？
13. Chroma的distance变成1-distance，能直接说是概率或余弦吗？
14. 工作记忆的24h过期会删除Chroma画像和情景摘要吗？
15. 画像取limit1为什么不等于最新？
16. 模板里的MEMORY_MAX_TOKENS是否真的限制prompt？
17. Skill关键词没命中时，其中禁止事项还生效吗？
18. /metrics存在为什么不代表业务Counter在正确增长？
19. LLMJudge给accuracy=.9能证明政策正确吗？
20. 你会选哪个缺陷先修，怎样用可重复输入证明修好了？

若一个答案需要查阅：返回对应函数页，将相关行号与一条因果解释写进自己的笔记。不要背本文的长段落，要练习用一两句话说明“这个输入触发这条分支，所以状态变成这样”。

## 建议完成的一个个人工程练习

任选一项单独做，先不要同时改三处：

- 修复压缩顺序，增加真实Redis集成检查，再考虑并发原子性。
- 给知识片段增加稳定ID，改工具去重，并记录来源到ChatResponse。
- 抽取ChatService，让CLI与评测复用HTTP同一业务链，修正entities差异。

这些练习尚未由本次解读任务执行。完成后保留“原输入→错误结果→修改理由→新结果→尚未解决边界”，这份证据会成为面试里最有价值的个人部分。
