# 这套文档如何维护

输入是当前项目源码和人工分析；输出是逐行阅读页、覆盖清单、配置表与验证记录。脚本不调用外部模型、不连接存储、不执行原项目示例命令。

| 文件 | 输入 → 输出 | 作用与边界 |
|---|---|---|
| content.py | 人工分析 → FILES字典 | 核心文件的输入输出、每个函数设计说明和关键行纠偏；更新源码后需要人工复核 |
| support.py | 部署/配置/材料分析 → 扩充FILES | 对非Python文件的作用和跨文件问题做说明 |
| build_docs.py | 原文本+FILES+AST → 逐文件页/索引/配置表/coverage.json | 自动维护原行号、签名、基础语句含义；复杂设计解释来自人工编写内容 |
| coverage.json | 生成时快照 → 验证依据 | 记录原文件行数、哈希和对应解读；.env不保存值或哈希 |
| verify.py | 源码AST+文档 → 06_验证记录.md | 检查覆盖与导航；隔离执行选定原方法，验证路由/缓存/压缩等边界 |

运行顺序：

```powershell
python 项目解读与面试指南/_maintain/build_docs.py
python 项目解读与面试指南/_maintain/verify.py
```

整体地图、请求推演、面试表达和改进路线是手工阅读文档，不由生成器覆盖。增加新业务文件时应补充导读和索引规则；生成器遇到未覆盖文件会报错，而不是默默漏掉。

增强方向：可以进一步把关键行注释绑定到AST节点而非固定行号，减少源码插行后的维护成本；仍须人工核对行为，不能仅凭自动逐行语法解释保证理解正确。
