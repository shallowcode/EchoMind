## 逐文件页怎么使用

每个原文件都有对应的 `逐文件/<原路径>.md`。页首写输入、输出、副作用和调用流；Python 中每个类/函数有人工编写的设计说明，之后逐行保留源码和行号；关键分支另加解释；页尾结合全项目列出未落地设计和增强方向。

共覆盖 **43 个文件、10,604 行、11 个 Python 文件、208 个类/函数节点**。脚本、配置、Skills、Git 忽略的演示数据、已有 Markdown 和 SVG 都包含在索引里。简单文本、注释、参数续行和重复绘图属性简述。`.env` 仅展示脱敏键名；数据库二进制、虚拟环境、Git 内部文件、IDE 编辑状态按用途登记，不伪造逐行解释。

文中证据分三种：**源码可见**（存在对应语句和调用）、**离线复现**（选定原方法在无外部依赖的隔离环境中运行）、**改进建议**（尚未实现）。模型回答示例是推演，不是本次真实模型输出；已有基线文件是历史记录，不是新实测结果。

## 改造前的定位（对应原00–07章）

EchoMind 是一个 **Python/FastAPI 实现的多角色客服编排原型**：围绕模型生成补上意图分流、知识检索、会话记忆、动态业务规则、工具可靠性和自动评测。控制流主要由 Python 规则决定，Agent 是共享调用实现、使用不同角色 prompt 的对象。

它已经有工程骨架，但还没有真实订单/退款执行、人工工单闭环、MCP 协议服务、完整权限体系或经过证明的生产质量指标。能够清楚讲出这些边界，通常比背“企业级全链路平台”更有说服力。
