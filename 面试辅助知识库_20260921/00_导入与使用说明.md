# EchoMind 面试辅助知识库：导入与使用

这套补充材料服务于项目讨论：帮助模型快速找到问题、解决机制、验证证据和实际边界。它不是猜题清单，也不代替你理解代码。

## 最简单的用法

1. 把 `原始参考/项目完整讲解.md` 和 `知识库补充材料_直接上传版.md` 上传到外接模型的项目知识库。
2. 把 `06_外接模型使用指令.txt` 放进该模型的系统指令或项目说明；它是行为约束，不是检索事实。
3. 填写 `07_个人贡献_待填写.md`，检查无误后再上传。没有填写的内容一律按未知处理。
4. 提问时提供当前话题和最近必要对话，例如“对方刚问退款重试怎么保证不重复，请给我三句要点”。模型只有收到这些文字才知道当前谈话内容。

本次已生成文件并邮件备份，没有配置语音识别、音频采集或外接模型连接。

## 按平台选择一种导入方式

- 普通文件知识库：上传完整讲解＋直接上传版。不要同时再上传 01—05 分册，它们是同一内容。
- 自建检索：使用 `08_事实卡片.jsonl`，每行一个独立事实单元；用 title、aliases、short_answer、details 和 boundary 构造检索正文，保留 id、kind、as_of、evidence 作为元数据。完整讲解另行按章节切分。
- 深入读代码：可额外上传 `09_核心代码证据摘录.md`。它提供实际代码片段，不是运行结果。
- 数字核验：查看 `10_历史评测数据.json`。数据来自历史 audit.json，未新调用付费模型。

可从每次检索 3—5 张相关卡片开始调试；这是起步建议，不是经过优化验证的参数。确保切片不把数值与分母、结论与边界拆开。

## 检索优先级

1. 个人贡献只采用本人明确确认的记录，源码不能补齐个人经历。
2. 当前实现看 2026-09-21 核对的 v2 卡片和代码依据；原完整讲解写于 2026-09-20。
3. 实验数字使用对应日期、样本和口径的报告。当前代码不代表历史评测当时的冻结版本。
4. design_inference 是依据实现的解释；proposed 是建议；illustration 是讲解例子，均不能当作已发生事实。
5. 旧版 wiki、简历包装、早期逐文件解读可能与 v2 冲突，不建议无版本标签混入。尤其不要混用 Java/Spring 包装与 Python 源码。

## 卡片怎么用

遇到“做了什么”查 A 类；“问题怎么解决”查 P 类；“为什么这么选”查 D 类；“效果和证据”查 E 类；“给个例子/有哪些限制”查 S 类。让模型先给 short_answer，追问时再取 details，并保留相关 boundary。

事实依据中的路径相对于原项目根目录；它们用于追溯，不要求另一设备拥有相同 Windows 路径。代码摘录与源码 SHA-256 清单已经随包提供。

更新代码后，更新受影响的卡片、摘录和清单；更新实验后新增带日期的成绩，不覆盖旧数字。未提供来源的信息不要让模型自行补全。
