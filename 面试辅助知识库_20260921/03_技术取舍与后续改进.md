## D01｜为什么采用显式规则规划
检索词：规则vs模型、规划器、为什么这样设计、可解释性。性质：依据代码的设计解释。

**简短讲法：** 从当前实现看，显式规划的优点是能列清任务和必需证据，便于控制写操作并定位遗漏；代价是规则覆盖有限，复杂表达需要扩展。

**展开要点：**

- 技术、订单、退款、人工、发票的触发条件可以直接审查。
- 若让模型建议任务清单，仍应由程序验证任务类型、工具范围和用户原始授权。
- 这里是依据代码做的设计解释，不是已核实的作者决策会议记录。

**边界：** 不能说模型规划一定更差，也没有规则规划与模型规划的独立对照结果。

**依据：** `supportflow/planning.py:86`（plan_tasks）；`supportflow/planning.py:76`（Subtask.allowed_tools）

## D02｜为什么 SQL 做事实来源
检索词：SQLite、数据库选型、Redis、Chroma、一致性。性质：依据代码的设计解释。

**简短讲法：** 订单、退款和会话需要明确状态与事务，所以由 SQL 保存事实；Redis 提供可选缓存，Chroma 提供可选语义检索。缓存和向量库失败不应抹掉核心业务记录。

**展开要点：**

- SQLite 便于本地运行，当前用 WAL 和 BEGIN IMMEDIATE 事务控制写入。
- 可选存储以投影方式补充能力，避免要求每次对话同时成功写入所有依赖。
- 取舍是 SQLite 写并发有限，跨 SQL/Chroma 仍有一致性窗口。

**边界：** 不能宣称已经验证高并发分布式部署；迁移数据库、持久化重试投影属于后续方案。

**依据：** `supportflow/store.py:40`（Store.tx）；`supportflow/service.py:325`（ChatService.chat）；`supportflow/knowledge.py:58`（Knowledge.add）

## D03｜为什么最终结果按任务直接呈现
检索词：结果合成、二次总结、延迟、遗漏。性质：依据代码的设计解释。

**简短讲法：** 程序直接按任务输出，是为了保留已验证的结果和失败项。再让模型自由总结可能遗漏某一项或改写状态，也会增加一次调用。

**展开要点：**

- render_tasks 为每项保留标题、答复和未完成原因。
- 取舍是表达可能重复、不如自由生成自然，需要在任务答复阶段控制简洁。

**边界：** 减少一次可能的生成步骤是结构上的判断；项目没有单独测出这一步节省了多少秒或费用。

**依据：** `supportflow/planning.py:164`（render_tasks）

## D04｜多 Agent 的收益和成本
检索词：为什么不用单Agent、成本、耗时、多Agent一定好吗。性质：设计解释＋历史记录。

**简短讲法：** 多 Agent 在这组开发任务上完成率更高，但总体耗时和费用也更高。应该根据复合任务覆盖收益做取舍，不能把 Agent 数量当作目标。

**展开要点：**

- single 与 multi 使用相同模型、工具和权限基础，single 也可使用全部业务工具。
- multi 同时增加显式任务规划、任务范围和增强检索；实验比较的是整个方案。
- 历史整体 HTTP P95：8.45 秒→12.78 秒；平均每任务模型费用估算：约 0.00445 元→0.00669 元。

**边界：** 没有独立消融就无法把收益拆给并行、规划或检索；也没有证据说所有简单问题都该使用多 Agent。

**依据：** `supportflow/service.py:33`（ToolAgent._call_llm）；`supportflow/service.py:426`（ChatService._run）；`评测结果/GLM-1200复核/audit.json:1`；`评测结果/GLM-1200复核/README.md:1`

## D05｜优先改进什么，怎样验证
检索词：下一步、不足、优化方向、改进计划。性质：待实施建议。

**简短讲法：** 优先处理会影响业务正确性的缺口：金额与订单的语义绑定、虚假提交表述、评测器误判；再优化存储投影、检索和成本。

**展开要点：**

- 金额绑定：建立多订单、多金额、否定、部分退款样本，检查工具参数是否唯一对应授权；不确定就澄清。
- 完成判断：将生成文案与结构化业务状态对齐，统计“没有写入却声称成功”的比例。
- 评测：修正错误码匹配，再在按模板族隔离的验证/验收集上跑固定版本，报告失败样本。
- 效率：分别消融改写、重排、任务拆分，比较完成率、P95、token 和费用，而不是只看单一成功率。

**边界：** 以上是建议实施的方案，不能说已经完成、已带来提升或是本人历史工作。

**依据：** `supportflow/service.py:33`（ToolAgent._call_llm）；`supportflow/planning.py:33`（Subtask.gaps）；`evaluation/full_chain.py:47`（verify）；`评测结果/GLM-1200复核/audit.json:1`；`评测结果/GLM-1200复核/README.md:1`
