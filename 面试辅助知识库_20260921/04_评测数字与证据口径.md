## E03｜延迟、费用和 token 的正确说法
检索词：P95、延迟、成本、token、性能。性质：历史实验记录。

**简短讲法：** 历史整体 HTTP 请求 P95 从 8.45 秒增加到 12.78 秒，平均每任务模型费用估算从约 0.00445 元增加到 0.00669 元；完成率提升伴随额外成本。

**展开要点：**

- HTTP 请求 P95 与整项任务 P95 不同；整项任务 P95 约 10.38 秒和 15.39 秒。

- 业务并发 2，部分时段另有串行意图评测流重叠；通过 ASGI 进程内 HTTP 测量，不含真实外部代理网络。
- 费用按历史 token 与 2026-09-08 版本价目表估算，不含人工、基础设施、优惠和未保存的中断调用。

**边界：** 这不是当前官方报价或真实账单，也不是完成了一次生产压测。不能把请求 P95 写成模型单次调用 P95。

## E05｜如何证明任务真的完成
检索词：评测方法、验证、证据、LLM Judge、可复现。性质：当前实现＋历史记录。

**简短讲法：** 评测通过实际 /chat 链路调用模型和业务工具，再检查成功工具、参数、答复条件及数据库状态。退款有没有真正创建，不能只让另一个模型看一句回答来判断。

**展开要点：**

- 订单核对查询工具；退款核对订单、金额、状态、数量和余额；人工流程检查工单状态及会话回写。
- 按方案隔离业务数据，保留逐例记录、冻结源码/数据哈希、运行配置和断点。
- LLM Judge 是可选主观评分；这批复核数据的 judge_valid 为 0，没有有效 Judge 成绩。

**边界：** 规则检查覆盖有限，仍需独立人工语义标注；52 项冻结哈希核对是历史审计结论，不意味着当前源码与当时完全一致。

**依据：** `evaluation/full_chain.py:47`（verify）；`evaluation/full_chain.py:212`（run_case）；`scripts/run_full_evaluation.py:1`；`评测结果/GLM-1200复核/audit.json:1`；`评测结果/GLM-1200复核/README.md:1`

## E06｜结果不支持哪些结论
检索词：实验局限、失败案例、公平对比、消融、验收。性质：历史实验记录。

**简短讲法：** 结果支持“这套多任务方案在本批开发任务上更完整”，不支持“模型本身变强”或“线上已经稳定”。样本相关性、方案差异和检查规则都会影响结论。

**展开要点：**

- 开发任务按模板参数展开，实例之间相关；不能把大量参数变体都当独立语义样本。
- 这次没有运行验证/验收集，没有独立人工金标复核自然语言正确性。
- 退款组两方案均为 49/75，说明提升并非覆盖所有业务类型。
- 仍有金额解析、部分退款和无依据提交表述等问题，失败记录保留。

**边界：** 不能只挑最高的一次小样本成绩，也不能声称多 Agent 在所有维度都更优。

**依据：** `评测结果/GLM-1200复核/audit.json:1`；`评测结果/GLM-1200复核/README.md:1`
